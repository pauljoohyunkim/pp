# Built-ins

## List built-ins

The PP compiler provides three built-ins for working with lists: `list_push`, `list_pop` and `list_clear`. Lists are implemented as heap-allocated dynamic arrays with the internal layout:

> These built-ins are unavailable in [freestanding mode](../language/11-freestanding.md)
> (`--ffreestanding`), together with the list type itself.

```
%pp.list = type { ptr, i64, i64, i64 }
; data, len, cap, elem_size
```

The built-ins are polymorphic over the element type `T`. The same code generation path handles any `T` that does not transitively contain a reference, with copy/drop semantics selected based on `pp_type_is_trivially_copyable` and `pp_type_needs_drop`.

### list_push

```pp
list_push(list, value)
```

Appends `value` to `list`.

* `list` must be a mutable list variable.
* `value` is copied into the list. For trivially copyable element types a `memcpy` is emitted, otherwise a copy helper generated by `pp_code_generator_ensure_copy_fn` is used.
* On the first push the element size is recorded in the list header.
* Capacity starts at 0 and grows to 4 on the first push, thereafter `cap *= 2` with `realloc`. The backing buffer is reloaded after a possible reallocation.

Example:
```pp
let v :: [int32];
list_push(v, 10);
list_push(v, 20);
```

### list_pop

```pp
x = list_pop(list)
```

Removes and returns the last element of `list`.

* Popping an empty list aborts at runtime.
* The element is copied out using a copy helper for non-trivial types, otherwise `memcpy`.
* `len` is decremented.

Example:
```pp
let v :: [int32] = [int32; 1,2,3];
let x :: int32 = list_pop(v); // x == 3
```

### list_clear

```pp
list_clear(list)
```

Removes all elements from `list`.

* If the element type needs drop, each element is dropped before the buffer is freed.
* The backing allocation is freed and the list header is reset to `data = null`, `len = 0`, `cap = 0`, `elem_size` is left unchanged until the next push.

Example:
```pp
list_clear(v);
```

### Restrictions

* List element types must not transitively contain a reference. The semantic analyzer rejects `list` declarations whose element type contains a reference, e.g. structs with reference fields.
* Lists are by value / copy semantics for the element. `list_push` copies the value; the source is not moved.
* Indexing into a list or array is **undefined behavior** if the index is out of bounds. No runtime bounds check is performed. `list_pop` is the only list operation that aborts on an empty container.

### Implementation notes

* All three built-ins are implemented inline in `src/pp_code_generator.c`:
  * `pp_code_generator_generate_rvalue_list_push`
  * `pp_code_generator_generate_rvalue_list_pop`
  * `pp_code_generator_generate_rvalue_list_clear`
* No separate runtime sources are used.
* `list_clear` currently frees the backing buffer and resets capacity to zero. Keeping capacity on clear is a possible future optimisation.
